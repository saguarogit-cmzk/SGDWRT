### 2.1 Nalaz — dva zadana izlaza (default gateway), LAN pobjeđuje WAN

**Trenutno stanje:**
```
default via 192.168.50.1 dev br-lan proto static          <- bez metrike = metrika 0
default via 192.168.205.1 dev eth1 proto static metric 10
```
**Verifikacija:** `ip route show` — verificirano.

**Nalaz:** LAN sučelje ima upisan gateway (`network.lan.gateway='192.168.50.1'`) pa
ima zadanu rutu s metrikom 0, koja je **jača** od WAN rute (metrika 10). Sav promet
koji uređaj sam pokreće (DNS upiti, provjere ažuriranja, banIP liste, e-mail,
NTP) izlazi na internet kroz **LAN** stranu, a ne kroz WAN. Promet korisnika ide
ispravno kroz WAN jer njime upravlja mwan3 (`mwan3 status` → `wan (100 %)`).

**Rizik:** SREDNJI u laboratoriju, VISOK u produkciji. U produkciji bi to značilo
da router zaobilazi vlastiti firewall i banIP zaštitu za sav svoj promet.

**Preporuka:** LAN sučelje u ulozi lokalne mreže **ne smije imati gateway**.
Ako se LAN koristi kao pričuvna internet veza (kao sada u laboratoriju), toj se
ruti treba dati veća metrika od WAN-a.

**Naredba:**
```sh
# ako je LAN samo lokalna mreža (produkcija):
uci delete network.lan.gateway; uci delete network.lan.dns; uci commit network
# ako LAN ostaje pričuvna veza (laboratorij):
uci set network.lan.metric=20; uci commit network
/etc/init.d/network reload
```
**Utjecaj:** kratki prekid usmjeravanja (< 2 s). **Prioritet: VISOKO.**

### 2.2 Nalaz — eth3 bez zone i bez uloge

**Trenutno stanje:** eth3 je DOWN, nije član nijednog bridgea, nema firewall zonu.
**Nalaz:** nije greška — to je slobodan port, spreman za DMZ ili WiFi pristupnu
točku preko čarobnjaka *Mreža → Dodatne mreže → Cijeli port*.
**Prioritet: INFORMATIVNO.**

### 2.3 MTU, MAC, brzina portova

**Nije moguće verificirati iz dostupnih podataka** — `ethtool` nije instaliran,
pa brzina/duplex portova nisu očitani. MTU nije nigdje ručno mijenjan (koristi se
zadanih 1500), a `mtu_fix='1'` na WAN zoni je uključen (MSS clamping radi).

## 5. Firewall zone i pravila

**Zadane politike (verificirano):**
```
input REJECT / output ACCEPT / forward REJECT / syn_flood 1
```
Ovo je ispravno i sigurno.

**Zone:**

| Zona | input | output | forward | masq | Nalaz |
|---|---|---|---|---|---|
| lan | ACCEPT | ACCEPT | ACCEPT | — | standardno; vidi 12.2 |
| wan | REJECT | ACCEPT | DROP | **1** | ispravno |
| sagwg (WireGuard) | **ACCEPT** | ACCEPT | REJECT | — | **vidi nalaz 5.1** |
| sagovpn (OpenVPN) | **ACCEPT** | ACCEPT | REJECT | — | **vidi nalaz 5.1** |

**Prosljeđivanja:** lan→wan, sagwg→lan, sagwg→wan, sagovpn→lan, sagovpn→wan.
Nema pravila tipa "sve prema svemu". Nema pristupa LuCI-ju ni SSH-u s WAN-a
(verificirano: `input_wan` nema ACCEPT za 22/80/443/8443).

### 5.1 Nalaz — VPN zone imaju `input ACCEPT` (pun pristup samom ruteru)

**Trenutno stanje:** `firewall.sag_wg_zone.input='ACCEPT'` i
`firewall.sag_ovpn_zone.input='ACCEPT'`.
**Verifikacija:** `uci show firewall` + `nft list chain inet fw4 input_sagwg` — verificirano.

**Nalaz:** korisnik spojen na VPN može doći na **sve servise samog uređaja**:
SSH (22), LuCI (80 i 443), Saguaro (8443), DNS (53). To vrijedi i za korisnika
koji je u Saguaru postavljen kao *ograničen* — pravila po korisniku uređuju
samo promet **kroz** router (forward), ne i promet **prema** routeru (input).

**Rizik:** VISOK. VPN je zamišljen kao pristup mreži, ne kao pristup upravljanju.
Kompromitirani laptop s VPN profilom dobiva pokušaj prijave na upravljanje.

**Preporuka:** VPN zone postaviti na `input REJECT` i eksplicitno propustiti samo
DNS i ICMP; pristup upravljanju dopustiti samo pojedinim VPN adresama
(npr. administratoru), i to kroz postojeći modul *Sustav → Pristup upravljanju*.

**Naredba (primjer za WireGuard, isto vrijedi za sagovpn):**
```sh
uci set firewall.sag_wg_zone.input='REJECT'
uci set firewall.sag_wg_dns=rule
uci set firewall.sag_wg_dns.name='WG DNS'
uci set firewall.sag_wg_dns.src='sagwg'
uci set firewall.sag_wg_dns.proto='tcp udp'
uci set firewall.sag_wg_dns.dest_port='53'
uci set firewall.sag_wg_dns.target='ACCEPT'
uci commit firewall && /etc/init.d/firewall restart
```
**Utjecaj:** VPN korisnici gube pristup LuCI-ju/SSH-u preko tunela (namjerno).
**Prioritet: VISOKO.** Trajno rješenje: promijeniti generiranje zona u
`core/wireguard.go` i `core/openvpn.go` + dodati kvačicu "dopusti upravljanje
uređajem preko VPN-a" (zadano isključena).

### 5.2 Nalaz — stvarni firewall ne odgovara konfiguraciji (zaostali lanci)

**Trenutno stanje:** u živom nftables skupu postoje lanci `input_testvlan`,
`forward_testvlan`, `input_dmz`, `forward_dmz`, iako te zone **više ne postoje**
u `/etc/config/firewall`.

**Verifikacija:**
```
nft list table inet fw4 | grep chain input_   -> 12 lanaca
fw4 print        | grep chain input_          ->  8 lanaca
nft list chain inet fw4 input_dmz             -> prazan, nereferenciran
```
Verificirano.

**Nalaz:** `/etc/init.d/firewall reload` u OpenWrt 25.x **ne briše** lance zona
koje su u međuvremenu obrisane iz konfiguracije. Ostaju prazni i nereferencirani,
pa **ne propuštaju promet** — nisu sigurnosni problem, ali su dokaz da se stvarno
stanje i konfiguracija razilaze. Kod dovoljno izmjena to postaje smetlište koje
otežava svaki budući audit.

**Rizik:** NIZAK (sigurnosno), SREDNJI (održavanje i povjerenje u nalaze).

**Preporuka:** kod **brisanja** mreže/zone Saguaro treba pozvati
`firewall restart` umjesto `reload`. Izmjena je u `core/vlan.go` (redak ~404) i
svugdje gdje se briše zona.

**Odmah:** `/etc/init.d/firewall restart` čisti zaostatke.
**Prioritet: SREDNJE.**

### 5.3 Ostala pravila

- `Allow-Ping` s WAN-a je uključen — informativno; za poslovni firewall
  preporuka je ograničiti na `limit 5/sec` ili isključiti.
- `Allow-IPSec-ESP` i `Allow-ISAKMP` s WAN-a prema LAN-u su **zadana OpenWrt
  pravila** koja propuštaju IPsec prema LAN-u iako IPsec nije instaliran.
  Prazan hod; preporuka je obrisati ih dok se IPsec ne uvede. **Prioritet: NISKO.**
- `sag_or_42fce4b9` (OVPN 10.7.0.2 → 192.168.50.10:443) — **nije zaostatak**,
  odgovara postojećem klijentu `goran-laptop` u bazi. Ispravno.
- Nijedno pravilo nema `log` — nema zapisa o odbijenom prometu.
  **Prioritet: SREDNJE** (vidi poglavlje 19).

## 7. Usmjeravanje (routing)

**Verificirano (`ip route`, `ip rule`, `mwan3 status`):**

- mwan3 pravila su aktivna: `iif eth1 lookup 1`, `iif br-lan lookup 2`,
  fwmark politike 0x100/0x200, blackhole/unreachable za pale veze — sve ispravno.
- Politika `sag_policy`: wan (metrika 1) primarno, lan (metrika 2) pričuvno.
  Trenutačno `wan (100 %)` — **failover radi**, provjereno ranije i uživo
  (isključenje WAN-a → promet prešao na pričuvnu vezu → povratak).
- Nema routing petlji, nema neaktivnih gatewaya, povratne rute postoje za sve
  interne mreže (izravno spojene).
- OSPF (bird2) je instaliran, **trenutačno nije konfiguriran** — nema
  `/etc/bird.conf` u aktivnoj upotrebi.

**Nalaz 7.1 — metrike:** vidi 2.1 (LAN default s metrikom 0).
**Nalaz 7.2 — IPv6 politika:** `Current ipv6 policies: sag_policy: default` —
IPv6 promet ne prolazi kroz failover. **Prioritet: SREDNJE.**
**Nalaz 7.3 — `rp_filter=0`:** anti-spoofing na razini kernela je isključen.
Za multi-WAN **ne smije** se postaviti na 1 (strogo) jer bi razbio failover;
ispravna vrijednost je **2 (labavo)**.
```sh
echo "net.ipv4.conf.all.rp_filter=2" >> /etc/sysctl.d/99-saguaro.conf
echo "net.ipv4.conf.default.rp_filter=2" >> /etc/sysctl.d/99-saguaro.conf
sysctl -p /etc/sysctl.d/99-saguaro.conf
```
**Prioritet: SREDNJE.**

### 8.1 Nalaz — dnsmasq sluša i na WAN adresi

**Trenutno stanje:**
```
udp 192.168.205.50:53   <- WAN adresa
tcp 192.168.205.50:53
```
**Verifikacija:** `netstat -tulnp` — verificirano.
**Nalaz:** DNS servis je vezan i na WAN sučelje. Trenutačno ga štiti samo
firewall (`wan input REJECT`). Ako se ikad doda pravilo koje otvara WAN input,
uređaj postaje **otvoreni DNS resolver** (koristi se za DDoS pojačanje).
Obrana u dubinu nalaže da servis uopće ne sluša na WAN-u.
**Rizik:** SREDNJI (danas ublažen firewallom).
**Preporuka:**
```sh
uci add_list dhcp.@dnsmasq[0].notinterface='wan'
uci add_list dhcp.@dnsmasq[0].notinterface='sag_wan2'
uci commit dhcp && /etc/init.d/dnsmasq restart
```
**Prioritet: SREDNJE.** Trajno: dodati u `install.sh` i u DNS modul.

## 9. OpenVPN

**Stanje: implementirano i pokrenuto.**

**Verificirano:**

- Sučelje `tun_sag` 10.7.0.1/24 gore, zona `sagovpn`, firewall pravilo za 1194 postoji.

  `ccd-exclusive`, `topology subnet`, `tls-crypt`, `dh none`, `keepalive 10 60`,

### 9.1 Nalaz — nedostaje eksplicitno pojačanje kriptografije

**Trenutno stanje:** serverska konfiguracija **nema**: `data-ciphers`,
`tls-version-min`, `user nobody` / `group nogroup`, `crl-verify`.

**Verifikacija:** pregled `/var/etc/openvpn-sag_server.conf` i `core/openvpn.go` —
verificirano.

**Nalaz:** OpenVPN 2.7 po zadanom pregovara AES-256-GCM i TLS 1.3, pa sustav
**nije nesiguran**, ali se oslanja na zadane vrijednosti umjesto da ih propisuje.
Tri konkretna nedostatka:
1. **Nema CRL-a.** Oduzimanje pristupa oslanja se isključivo na `ccd-exclusive`
   (brisanje CCD datoteke). Certifikat ostaje kriptografski valjan — ako se CCD
   ikad vrati iz backupa, otpušteni zaposlenik se opet spaja.
2. **Servis radi kao root.** Nema `user nobody` / `group nogroup`.
3. **Nema propisanog šifrarnika ni minimalne verzije TLS-a.**

**Usporedba sa SGSU:** projekt `C:\install\SGSU`
(`internal/adapters/openvpn/openvpn.go`) to već ima riješeno — generira
`crl-verify`, `data-ciphers AES-256-GCM`, `user nobody`, `remote-cert-tls server`,
funkciju `GenerateCRL()` i rok valjanosti po klijentu (`notAfter`). **To je
gotov predložak koji treba prenijeti u SGSWRT.**

**Preporuka (izmjena u `core/openvpn.go`, generiranje serverske konfiguracije):**
```
data-ciphers AES-256-GCM:CHACHA20-POLY1305
data-ciphers-fallback AES-256-GCM
tls-version-min 1.2
remote-cert-tls client
user nobody
group nogroup
crl-verify /opt/saguaro/etc/ovpn/crl.pem
```
i u klijentskoj: `data-ciphers AES-256-GCM:CHACHA20-POLY1305`, `tls-version-min 1.2`,
`auth-nocache`.
**Utjecaj:** postojeći klijentski profili i dalje rade. **Prioritet: VISOKO.**

### 9.2 Nalaz — DNS koji se gura klijentima

**Trenutno stanje:** `push "dhcp-option DNS 192.168.50.222"` (LAN adresa uređaja).
**Nalaz:** radi jer se gura i ruta za 192.168.50.0/24, ali ispravnije je gurati

preko **WireGuarda**, ne OpenVPN-a (jednostavnije, brže, stabilnije).

## 19. Logovi i centralizirano logiranje

**Trenutno stanje (verificirano):**
- `logd -S 128` — **128 KB kružnog spremnika u RAM-u**.
- `system.@system[0].log_size='128'`, **nema `log_ip`** → syslog prosljeđivanje
  isključeno.
- Nema rotacije na disk, nema trajne pohrane. **Nakon svakog restarta svi logovi
  nestaju.**
- U trenutnom ispisu 128 KB pokriva **manje od 2 minute** rada (dominiraju SSH
  prijave ovog audita) — u praksi to znači da se povijest gubi gotovo odmah.
- Firewall pravila **nemaju `log`** — nema zapisa o odbijenom prometu.
- Saguaro ima vlastiti zapis događaja u SQLite bazi (tablica `events`) — to
  preživljava restart, ali pokriva samo Saguarove događaje.

### 19.1 Nalaz — nema trajnog logiranja

**Rizik:** VISOK za poslovni firewall. Bez logova nema odgovora na pitanje
"što se dogodilo sinoć u 23:40". Za incident, reklamaciju ili reviziju to je
neupotrebljivo.

**Ključna okolnost:** uređaj ima **220 GB slobodnog diska**. Nema razloga da
logovi žive u RAM-u.

**Preporuka (dva koraka):**

1. **Odmah — povećati spremnik i pisati na disk:**
```sh
uci set system.@system[0].log_size='1024'        # 1 MB u RAM-u
uci set system.@system[0].log_file='/opt/saguaro/log/system.log'
uci set system.@system[0].log_remote='0'
uci commit system && /etc/init.d/log restart
# + dnevna rotacija preko crona
echo '0 4 * * * mv /opt/saguaro/log/system.log /opt/saguaro/log/system.$(date +\%F).log; /etc/init.d/log restart; find /opt/saguaro/log -name "system.*.log" -mtime +30 -delete # sag-logrotate' >> /etc/crontabs/root
/etc/init.d/cron restart
```

2. **Zatim — prosljeđivanje na vanjski poslužitelj.** Saguaro to **već ima**
   (*Sustav → Syslog*, `core/system.go`) — samo treba upisati adresu.

**Preporuka koje događaje trajno čuvati:** prijave (uspješne i neuspješne),
promjene konfiguracije, WAN gore/dolje, VPN spajanja, banIP blokade, restart.

**Preporučeni odredišni sustavi (svi rade s običnim syslogom):** Graylog,
Grafana Loki, Zabbix, ELK, ili najjednostavnije — `rsyslog` na Linux serveru
odnosno syslog na NAS-u (Synology/QNAP ga imaju ugrađenog).
**Prioritet: VISOKO.**

## 21. Obavijest o promjeni javne IP adrese

**Nije implementirano.** Nema praćenja javne IP adrese ni u kodu ni na uređaju.

**Predloženi sustav (uklapa se u postojeći `monitorLoop`):**

1. Svakih 5 minuta dohvatiti javnu adresu (npr. `https://api.ipify.org`, uz
   pričuvni izvor).
2. Usporediti s vrijednošću u `settings` (`wan_public_ip`).
3. Ako se razlikuje: upisati događaj u `events` s vremenom promjene.
4. Poslati e-mail (uz zaštitu od ponavljanja).
5. Po potrebi pokrenuti osvježavanje DDNS-a.
6. Ako se nije promijenila — ne raditi ništa.

**Dodatno se preporučuje:**
- **Zasebna provjera po WAN-u** — vezati upit na sučelje (`curl --interface eth1`),
  jer inače kod multi-WAN-a mjeriš adresu one veze koja je trenutačno aktivna.
- **Detekcija CGNAT-a** — ako je adresa na WAN sučelju iz raspona
  `100.64.0.0/10`, ili se razlikuje od javne adrese, uređaj je iza operaterskog
  NAT-a → **port forwardi i VPN izvana neće raditi**. Ovo je vrlo korisno
  upozorenje jer objašnjava klasu problema koju je inače teško dijagnosticirati.
- **IPv4 i IPv6** zasebno.
- Radi jednako za DHCP i PPPoE (mjeri se stvarna izlazna adresa, ne lokalna).

**Prioritet: VISOKO** (mala izmjena, velika korist, temelj za DDNS).

## 24. Backup i povrat konfiguracije

**Verificirano:**
- Automatski backup **prije svake izmjene** — u `/opt/saguaro/backup` je 15 kopija
  pojedinačnih konfiguracija (network, firewall, openvpn, sqm, system) s vremenskim
  oznakama. **Radi.**
- Puni backup: `up-20260730-155914-full-20260730-155842.tar.gz` (14 KB) — sadrži
  OpenWrt konfiguraciju + Saguaro bazu + certifikate + token.
- Raspored: `0 3 * * * /opt/saguaro/etc/backup-cron.sh # sag-backup` — **aktivan.**
- Prava: cijeli direktorij `drwx------`, arhive `-rw-------`. **Ispravno.**
- Ciklus backup → preuzimanje → vraćanje → restart **ranije je verificiran uživo.**
- `sysupgrade -b` obuhvaća i `/etc/bird.conf` i `banip.allowlist` — provjereno ranije.

### 24.1 Nalaz — backup postoji samo na uređaju

**Trenutno stanje:** sve kopije su na `/opt/saguaro/backup` — na **istom disku**
koji backup treba zaštititi.
**Nalaz:** ovo nije backup, nego povijest izmjena. Kvar diska ili krađa uređaja
znači gubitak svega.
**Preporuka:** automatsko slanje izvan uređaja. Redoslijedom praktičnosti:
1. **SCP/SFTP na Linux server ili NAS** — `scp` već postoji, treba samo ključ i
   redak u `backup-cron.sh`. **Najjednostavnije i najpreporučljivije.**
2. **Git repozitorij** — odličan za `/etc/config` jer daje i povijest promjena
   (vidi poglavlje 25). **Ne** za pune arhive s ključevima.
3. Cloud storage (`rclone`) — moguće, veći paket.
4. **E-mail — ne preporučuje se** za pune arhive (sadrže privatne ključeve).
**Prioritet: VISOKO.**

### 24.2 Nalaz — backup nije šifriran

**Trenutno stanje:** obična `tar.gz` arhiva.
**Nalaz:** arhiva sadrži: **WireGuard privatni ključ, OpenVPN CA i serverski
privatni ključ, tls-crypt ključ, Saguaro API token, otiske lozinki, SMTP lozinku,
DDNS token.** Tko dobije arhivu — dobio je cijeli VPN i upravljanje.
**Preporuka:** šifrirati prije slanja izvan uređaja:
```sh
# u backup-cron.sh, nakon stvaranja arhive
openssl enc -aes-256-cbc -pbkdf2 -salt -in "$ARCHIVE" -out "$ARCHIVE.enc" -pass file:/opt/saguaro/etc/backup.key
```
Idealno: dodati u Saguaro polje "lozinka za backup arhive" i šifrirati sve
preuzete arhive. **Prioritet: VISOKO.**

### 24.3 Nalaz — nema backupa prije nadogradnje firmwarea

Saguaro radi puni backup prije **vlastite** nadogradnje (verificirano u
`core/update.go`), ali `sysupgrade` (nadogradnja OpenWrt-a) može se pokrenuti iz
LuCI-ja bez Saguarovog backupa. **Preporuka:** dodati `/lib/upgrade/keep.d/`
zapis i hook koji prije `sysupgrade`-a pokrene Saguarov puni backup.
**Prioritet: SREDNJE.**

## 26. Automatske nadogradnje

**Verificirano:**
- Sustav paketa: **apk** (OpenWrt 25.x), indeks osvježen — 11 256 paketa dostupno.
- `apk list -u` → **prazno**: nema paketa za nadogradnju, sve odgovara 25.12.4.
- `luci-app-attendedsysupgrade` **instaliran** → nadogradnja firmwarea uz čuvanje
  paketa i konfiguracije je dostupna kroz LuCI.
- Prostora ima 220 GB.
- Saguaro se nadograđuje odvojeno (GitHub izdanja), uz puni backup prije zamjene.

**Preporuke:**

1. **Ne uključivati automatsko ažuriranje svih paketa.** Na OpenWrt-u `apk upgrade`
   preko cijelog sustava zna razbiti kombinaciju kernela i modula. Ovdje je
   dodatni razlog `kmod-*` paketi vezani uz točnu verziju kernela (6.12.87).
2. **Sigurno je ažurirati** pojedinačno i ciljano: `banip`, `adblock-fast`,
   `ddns-scripts`, `luci-*` — to su skripte/aplikacije bez veze s kernelom.
3. **Potpuni firmware upgrade** treba kad izađe nova verzija (25.12.5, 26.x) ili
   kad je objavljena sigurnosna zakrpa kernela/openssl-a.
4. **Postupak nadogradnje firmwarea:**
   - Saguaro: puni backup + **preuzeti ga na računalo**.
   - Attended Sysupgrade s uključenim "keep settings" (čuva i popis paketa).
   - Nakon podizanja: `apk list -I | wc -l` usporediti s 270, provjeriti
     `mwan3 status`, `banip status`, `nft list tables`, prijavu u Saguaro.
5. **Rollback:** x86 uređaj nema dual-boot particiju → povratak znači ponovni
   `sysupgrade` na staru sliku + vraćanje backupa. **Zato je off-device backup
   (24.1) preduvjet za svaku nadogradnju.**

**Prioritet: SREDNJE** (radnja, ne popravak).

### 28.1 Nalaz — repozitorij se zove SGSWRT, kod još pokazuje na SGDWRT

**Trenutno stanje:**
```
git remote -v      -> https://github.com/saguarogit-cmzk/SGDWRT.git
scripts/install.sh -> REPO="saguarogit-cmzk/SGDWRT"
docs/PRIRUCNIK.md  -> .../SGDWRT/main/scripts/install.sh
web/index.html:975 -> .../SGDWRT/main/scripts/install.sh
```
**Verificirano.**
**Nalaz:** GitHub trenutačno preusmjerava staro ime na novo, pa sve **još radi**.
Ali čim netko zauzme staro ime `SGDWRT`, `install.sh` na novom uređaju povlačio bi
**tuđi kod i izvršavao ga kao root** (`wget … | sh`). To je stvaran rizik lanca
opskrbe, ne teoretski.
**Rizik:** SREDNJI danas, VISOK ako staro ime bude zauzeto.
**Preporuka:** ispraviti sva četiri mjesta na `SGSWRT`.
**Prioritet: VISOKO** (trivijalan popravak).

### 28.2 Nalaz — `uciQuote` ne štiti od novog reda (ubacivanje naredbi)

**Trenutno stanje** (`core/firewall.go:1103`):
```go
func uciQuote(s string) string {
	if !strings.ContainsAny(s, " \t") {
		return s
	}
	return "'" + strings.ReplaceAll(s, "'", "") + "'"
}
```
**Nalaz:** funkcija navodnike stavlja **samo ako niz sadrži razmak ili tabulator**.
Naziv pravila poput
```
web
delete firewall
commit firewall
```
(bez ijednog razmaka, s novim redovima) prolazi **necitirano** u `uci batch`, koji
čita redak po redak → ubačene se naredbe izvršavaju. Rezultat: brisanje cijele
firewall konfiguracije. Isto vrijedi i za `update_url` u DDNS modulu, koji nije
ni validiran.

**Verifikacija:** pregled `validateForward` (provjerava samo `Name != ""`) i
`validateRule` — nijedno ne odbacuje kontrolne znakove. Verificirano u kodu.

**Rizik:** SREDNJI. Zloupotrebu može izvesti **samo prijavljeni administrator**,
koji ionako smije sve — pa ovo nije eskalacija ovlasti. Ali je stvaran problem
integriteta: dovoljno je da netko zalijepi tekst s prijelomom retka i konfiguracija
se tiho pokvari.

**Preporuka:** odbaciti sve kontrolne znakove pri validaciji **i** uvijek citirati:
```go
func uciQuote(s string) string {
	s = strings.Map(func(r rune) rune {
		if r < 0x20 || r == 0x7f { return -1 }   // makni CR, LF, TAB, ostalo
		return r
	}, s)
	return "'" + strings.ReplaceAll(s, "'", "") + "'"
}
```
Uz to u `validate*` funkcijama vratiti 400 ako ulaz sadrži `\n` ili `\r`, te
validirati `UpdateURL` (`url.Parse` + shema http/https).
**Prioritet: VISOKO.**

## 30. Zbirni nalazi po prioritetu

### KRITIČNO
*Nema nalaza ove razine.* Uređaj nije izložen internetu s otvorenim upravljanjem,
zadane politike su restriktivne, tajne su ispravno zaštićene na datotečnoj razini.

### VISOKO

1. **VPN zone imaju `input ACCEPT`** — VPN korisnici dosežu SSH/LuCI/Saguaro na
   ruteru bez obzira na "ograničena" pravila. (5.1)
2. **banIP filtrira `br-lan` umjesto WAN-a** — 16 495 zloćudnih adresa blokira se
   na krivoj strani. (14.1)
3. **Dva zadana gatewaya, LAN pobjeđuje WAN** — promet uređaja izlazi kroz LAN;
   uzrok nalaza 2. (2.1)
4. **SSH prijava lozinkom uključena**, a root lozinka se mora smatrati
   kompromitiranom. (12.2)
5. **Zadana lozinka `Sgs#2026` javno je poznata i ista na svakoj instalaciji** —
   treba prisiliti promjenu pri prvoj prijavi. (12.5)
6. **OpenVPN bez `crl-verify`, `data-ciphers`, `tls-version-min`, `user nobody`** —
   posebno: oduzimanje pristupa oslanja se samo na CCD. (9.1)
7. **Logovi žive samo u RAM-u (128 KB) i nestaju pri restartu**, syslog
   prosljeđivanje nije uključeno. (19.1)
8. **Backup postoji samo na uređaju i nije šifriran**, a sadrži sve privatne
   ključeve. (24.1, 24.2)
9. **E-mail upozorenja pokrivaju 2 od ~20 traženih događaja**; nema WAN-down,
   promjene javne IP, VPN statusa, restarta, pragova resursa. (20)
10. **Nema praćenja javne IP adrese** ni detekcije CGNAT-a. (21)
11. **`uciQuote` dopušta ubacivanje naredbi kroz novi red.** (28.2)
12. **`install.sh` i git remote pokazuju na staro ime `SGDWRT`** — rizik lanca
    opskrbe ako to ime netko zauzme. (28.1)

### SREDNJE

13. Zaostali nftables lanci — `reload` ne briše obrisane zone, treba `restart`. (5.2)
14. dnsmasq sluša na WAN adresi. (8.1)
15. LuCI bez preusmjeravanja na HTTPS; `luci-app-package-manager` na uređaju kod klijenta. (12.1, 18.1)
16. Saguaro i LuCI slušaju na svim sučeljima; management ACL postoji ali nije uključen. (12.3)
17. Nedostaju sigurnosna HTTP zaglavlja i eksplicitni `MinVersion` za TLS. (12.4)
18. `rp_filter=0` — postaviti na 2 (labavo, zbog multi-WAN-a). (7.3)
19. banIP: IPv6 isključen, BCP38 isključen, blokade se ne zapisuju. (14.2)
20. IPv6 ne prolazi kroz mwan3 politiku. (7.2)
21. Nema audita "tko je što promijenio" ni diffa; preporuka: `/etc/config` u Git. (25)
22. Nema ograničenja brzine za ICMP s interneta. (15)
23. DDNS token treba pisati u datoteku s pravima 0600. (22.1)
24. Nema backupa prije `sysupgrade`-a pokrenutog izvan Saguara. (24.3)
25. Nema temperature — nedostaje `kmod-hwmon-coretemp`. (1)
26. SMTP ne provjerava je li TLS stvarno uspostavljen; nema zaštite od poplave poruka. (20)
27. Nema WireGuard site-to-site veze (SGSU ima gotov predložak). (9.3)
28. SQM je spreman, ali nije uključen. (16)

### NISKO

29. Zaostatak `203.0.113.5` u banIP iznimkama. (28)
30. Zadana pravila `Allow-IPSec-ESP` / `Allow-ISAKMP` bez instaliranog IPseca. (5.3)
31. `Allow-Ping` s WAN-a bez ograničenja. (15)
32. OpenVPN gura LAN adresu kao DNS umjesto adrese u tunelu. (9.2)
33. Nema izlaznog SNAT-a po mreži. (6.1)
34. Nema DoT/DoH, AdGuarda, SNMP-a, WoL-a, UPS nadzora. (27)

## 31. Završni izvještaj

### 1. Sažetak sustava

Saguaro SGSWRT je vlastita upravljačka platforma (Go, jedan statički binary,
20 MB RAM-a) nad OpenWrt-om 25.12.4, s ~38 REST endpointa, vlastitim web
sučeljem i SQLite bazom, koja LuCI ostavlja netaknutim i upravlja isključivo
vlastitim `sag_*` zapisima, uz automatski backup prije svake izmjene.
Pokriva: WAN i multi-WAN s failoverom, VLAN-ove i mreže na portu, DMZ, DHCP,
DNS sa split-DNS-om i DNSSEC-om, firewall s port-forwardima, 1:1 NAT-om i
hairpin NAT-om za sve interne zone, WireGuard i OpenVPN s pravilima po
korisniku, banIP i blokadu domena, QoS, OSPF, DDNS, nadzor, backup i ažuriranje.
Hardver (4 jezgre, 8 GB, 220 GB) je znatno iznad potreba.

### 2. Verificirane funkcije (dokazano naredbama)

Firewall zone i politike · masquerade i MSS clamping · multi-WAN failover
(prebacivanje i povratak) · mwan3 praćenje i politike · DNS s DNSSEC-om ·
blokada domena (3 474) · banIP (16 495 zapisa, aktivan monitor za neuspjele
prijave) · WireGuard sučelje i port · OpenVPN servis, PKI i split-tunnel
konfiguracija · DHCP server · automatski backup prije izmjene i dnevni backup ·
Saguaro servis, prijava, API, zaštita od pogađanja lozinke · prava datoteka na
svim tajnama · vremenska zona Europe/Zagreb · sve pakete na zadnjoj verziji.

Ranije verificirano uživo (u prethodnim sesijama, nije ponovljeno danas):
split DNS, hairpin NAT za sve zone, DMZ na portu, VLAN čarobnjak, 1:1 NAT,
QoS s CAKE-om, sigurnosni povratak konfiguracije, ciklus backup/vraćanje/restart.

### 3. Nije bilo moguće verificirati

Stvarno spajanje WireGuard i OpenVPN klijenta (nijedan handshake nikad) ·
slanje e-maila (SMTP nije popunjen) · DDNS (nema računa) · rad s više javnih
IP adresa · load balancing · brzina i duplex portova (nema `ethtool`) ·
temperatura (nema senzora) · ponašanje nakon restarta i nestanka struje ·
ACME/Let's Encrypt.

### 4.–7. Problemi

Vidi poglavlje 30. Kritičnih nema; visokih 12; srednjih 16; niskih 6.

### 8. Nepotrebni servisi i paketi

Nema ih. Jedini kandidati za uklanjanje kod klijenta su
`luci-app-package-manager` (instalacija bilo čega kroz preglednik) i zadana
IPsec firewall pravila. `iptables-nft`/`ipset` izgledaju suvišno, ali ih traži
mwan3 — ne dirati.

### 9. Nedostajuće sigurnosne funkcije

Trajno logiranje · centralizirani syslog · upozorenja o kritičnim događajima ·
prisilna promjena zadane lozinke · zatvaranje VPN zona prema upravljanju ·
CRL za OpenVPN · šifriran backup izvan uređaja · anti-spoofing (rp_filter/BCP38) ·
audit trag s korisnikom i diffom · sigurnosna HTTP zaglavlja.

### 10. Moguće dodatne funkcije

Suricata IDS/IPS (hardver to nosi) · WireGuard site-to-site · 4G/5G pričuvna
veza preko USB modema · SNMPv3 · UPS nadzor (`nut`) · Git povijest
konfiguracije · zabrana vanjskog DNS-a klijentima · DoT/DoH · izlazni SNAT po
mreži · Wake-on-LAN · Captive portal i RADIUS za veće mreže.

### 11. Preporučena mrežna arhitektura

Vidi tablicu u poglavlju 4: WAN na eth1, DMZ na cijelom portu eth3, a na eth0
tagirani VLAN-ovi Management / Korisnici / Serveri / Pisači / IoT / Gosti.
Upravljanje (Saguaro, LuCI, SSH) dopustiti **samo iz Management VLAN-a**.
Gosti i IoT izolirani, samo internet. eth2 rezerviran za drugu internet vezu.

### 12. Preporučeni VPN sustav

**WireGuard kao primarni** (brz, u kernelu, jednostavan, radi iza NAT-a),
**OpenVPN kao pričuvni** za klijente koji WireGuard ne mogu. Oba split-tunnel,
oba s pravilima po korisniku, oba sa **zatvorenim pristupom upravljanju**
(nalaz 5.1). Site-to-site raditi WireGuardom. IPsec samo za tuđu opremu.

### 13. Preporučeni sustav e-mail upozorenja

Postojeći Saguarov SMTP klijent + zaseban poštanski račun s lozinkom aplikacije
+ obavezan TLS + zaštita od ponavljanja (ista poruka najviše 1× / 30 min).
Okidače dodati redoslijedom: WAN pao/vratio se → promjena javne IP → VPN
spojen/odspojen → restart uređaja → promjena konfiguracije → pragovi CPU/RAM/disk
→ neuspjele prijave → istek certifikata. Uz e-mail razmotriti Telegram za brze
alarme.

### 14. Preporučeni sustav nadzora

Kratkoročno: proširiti Saguarovu petlju nadzora (servisi, pragovi, latencija,
gubitak paketa). Srednjoročno: syslog na Graylog/Loki + SNMPv3 prema postojećem

### 15. Preporučeni sustav backupa

Postojeći automatski backup + **šifriranje (AES-256)** + **automatsko slanje na
NAS/Linux server preko SCP-a** + zaseban Git repozitorij za `/etc/config`
(povijest i diff) + obavezno preuzimanje pune arhive prije svake nadogradnje
firmwarea. Jednom u tri mjeseca provjeriti vraćanje na testnom uređaju.

### 16. Preporučeni plan nadogradnje

Ne uključivati automatsko ažuriranje. Mjesečno provjeriti `apk list -u` i
ažurirati samo skriptne pakete (banip, adblock-fast, ddns, luci). Firmware
nadograđivati kroz Attended Sysupgrade uz "keep settings", i to tek nakon
preuzetog punog backupa. Nakon svake nadogradnje odraditi testove 1, 14, 15, 21
iz poglavlja 29.

### Zaključak

## SPREMNO NAKON MANJIH ISPRAVAKA

**Obrazloženje.** Arhitektura je zdrava, hardver predimenzioniran, sve
funkcije koje uređaj treba imati kao mali poslovni firewall su prisutne i
većim dijelom dokazane. Nijedan nalaz ne zahtijeva preradu sustava — svi
nalazi visokog prioriteta su konfiguracijske izmjene ili male izmjene koda
koje stanu u **Fazu A i B, otprilike dva radna dana**.

Dvije stvari treba jasno razlikovati:

- **Popravci** (Faza A) — bez njih uređaj **ne smije** kod klijenta: otvorene
  VPN zone prema upravljanju, SSH s lozinkom i poznatom root lozinkom, javno
  poznata zadana lozinka, banIP na krivom sučelju, staro ime repozitorija u
  instalacijskoj skripti.
- **Dopune** (Faza B) — bez njih uređaj radi, ali "slijep je i nijem": nema
  trajnih logova, nema upozorenja, nema backupa izvan uređaja. Za nadzirani
  produkcijski firewall to je nužno.

Najveći preostali rizik nije nijedan pojedinačni nalaz, nego činjenica da
**nijedan VPN klijent, e-mail ni DDNS nikad nisu praktično isprobani** — to su
funkcije koje izgledaju gotovo, a dokazane nisu. Faza D (svježa instalacija +
puni popis testova iz poglavlja 29) mora se odraditi prije prve isporuke.
